# RS485 / Modbus RTU 使用说明

## 接线与默认参数

- PA2（USART2_TX）→ 485 芯片 DI。
- PA3（USART2_RX）← 485 芯片 RO。
- PA1（RS485_EN）→ DE 和 /RE：高电平发送、低电平接收。
- 默认从站地址 **1**；串口 **115200、8E1**。
- STM32F1 的 CubeMX 配置为 **9 Bits + Even + 1 Stop Bit**，有效数据是 8 位。
- TIM2 时钟 72 MHz，PSC=71，计数频率 1 MHz，ARR=1749。
- USART1 仍用于原来的调试、去皮命令和 VOFA+。

地址、发送有效电平、发送超时和数据过期阈值在 `App/app_config.h` 设置。
修改波特率或校验格式时，应在 CubeMX 的 USART2 中修改并重新生成；驱动会根据
USART2 参数计算 RTU 定时。当前启动日志中的串口格式文字对应默认 115200/8E1。

## 软件结构

- `RS485.c/.h`：独立的方向控制、逐字节中断接收、串口错误恢复和有超时的阻塞发送。
  成功发送时 HAL 等待 UART TC，确保最后一个停止位发完才释放总线。
  发送只能在主循环中调用；所有退出路径均恢复接收方向。
- `ModBus.c/.h`：RTU 从站收帧、CRC16、03/04 读寄存器、异常应答、广播静默。
  寄存器内容由回调提供，驱动不依赖 ADC 或业务模块。
- `App/app_modbus.c/.h`：绑定 USART2、PA1、TIM2，提供 ADC 寄存器表。
- `App/app_measure.c`：ADC 始终采集、去皮和滤波，并保存最近一次有效样本。
  USART1 的 `0`/`1` 只控制 VOFA 输出，不再停止 ADC 更新；`2` 仍执行去皮。

`app.c` 统一拥有 HAL UART 完成/错误回调，再分发至 shell 和 RS485。
TIM2 IRQ 的 `USER CODE BEGIN TIM2_IRQn 0` 调用 `App_ModBus_TimerIRQ()`，
在 HAL 清除更新标志之前原子处理超时，避免 USART2 与 TIM2 同时挂起时误结束新帧。
所有业务接入均位于 App 目录或 CubeMX 的 USER CODE 区。

Modbus 在 ADC 上电自检完成后才启动；先等 USART1 输出 `Ready` 再轮询。
不需要发送 `0`，485 即可读取数据。

## 只读寄存器表

**03（读保持寄存器）和 04（读输入寄存器）读取同一份数据。**
地址为报文中的零基地址。Modbus Poll 等软件若采用 1 基显示，需相应加 1。
一份读请求内的码值、电压、采样计数和时间来自同一次快照。

| 报文地址 | 03 常见编号 | 类型 | 含义 |
|---|---|---|---|
| 0x0000–0x0001 | 40001–40002 | int32 | 原始 ADC 码，保留符号，不去皮、不滤波 |
| 0x0002–0x0003 | 40003–40004 | float32 | 上述原始码换算的差分电压，mV |
| 0x0004–0x0005 | 40005–40006 | int32 | 去皮并滤波后的 ADC 码，与 VOFA CH3 相同 |
| 0x0006–0x0007 | 40007–40008 | float32 | 上述处理后码值对应的电压，mV，与 VOFA CH4 相同 |
| 0x0008 | 40009 | uint16 | 状态位，见下文 |
| 0x0009 | 40010 | uint16 | 当前 PGA 增益，默认 128 |
| 0x000A–0x000B | 40011–40012 | uint32 | 有效样本累计数 |
| 0x000C–0x000D | 40013–40014 | uint32 | 距最近有效采样的时间，ms |

每个寄存器先发高字节；32 位数先发高 16 位寄存器，即 **ABCD / Big Endian**。
int32 是补码；float32 是 IEEE-754 单精度。CRC16 则低字节先发。

例如 `00 10 62 4E` 表示原始码 1073742；
`3F 80 00 00` 作为 float32 表示 1.0 mV。

状态位：

| 位 | 含义 |
|---|---|
| bit0 | 已获得至少一次有效 ADC 样本 |
| bit1 | 正在去皮 |
| bit2 | 已有有效去皮零点 |
| bit3 | VOFA 输出已启用 |
| bit4 | 尚无有效样本，或最近有效样本已超过 1000 ms |

bit0 表示“曾获得有效样本”，新鲜度应同时检查 bit4；正常可用数据为
bit0=1 且 bit4=0。启动后第一份有效样本到来前，数据为 0，bit0=0、bit4=1，
样本年龄为 `0xFFFFFFFF`。ADC 失联或无效样本不会覆盖最后有效值，年龄持续增加，
避免把旧数值误当成新采样。

当前电压换算：

```text
Vdiff(mV) = ADC码 × APP_VREF_MV / (PGA增益 × 8388608)
```

`APP_VREF_MV` 当前为 **5000.0 mV**，是配置值。要提高绝对电压准确度，
请将其改为实际测量的 REFP0–REFN0 电压。原始电压包含桥路零点偏移，
处理后电压经过零点扣除和滤波；它们均不是重量或力值。

## 主站读取示例

主站设置：RTU、地址 1、115200、8 数据位、偶校验、1 停止位。
建议先用 100 ms 查询间隔、200 ms 响应超时进行联调。
以下是十六进制字节，包含 CRC；普通串口助手发送时需选择 HEX 发送。

读取原始码和对应电压：功能码 **03**、起始地址 **0**、数量 **4**：

```text
01 03 00 00 00 04 44 09
```

响应结构（RR 是 int32 码值，VV 是 float32 电压）：

```text
01 03 08 RR RR RR RR VV VV VV VV CRC低 CRC高
```

同样读取也可使用功能码 04。读取全部数据及状态时使用起始地址 0、数量 14。
具体报文可用主站软件自动计算 CRC。

请按 int32 / float32、ABCD 顺序显示，避免把两个寄存器分别当 uint16 读数。
需要码值与电压对应时，应在一次请求中一起读取。

## 协议范围与验证

- 03/04，每次 1–125 个寄存器；应用实际有效范围是 0x0000–0x000D。
- 不支持写寄存器；不支持的功能码返回异常 01，地址越界返回异常 02，
  非法数量或请求长度返回异常 03。
- CRC 错误、其他从站地址、广播地址 0、UART 错误和超长帧不应答。
- 大于 19200 波特率使用 t1.5=750 us、t3.5=1750 us；低速按字符时间计算。
  字符间隔检查会补偿 RXNE 在字符结束时发生的一个字符时间。
- 一帧接收缓冲和一个待处理帧；主站应等待应答后再发下一请求。
  待处理帧未消费时后续完整帧会丢弃，避免覆盖正在应答的数据。

固件构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File MDK-ARM/tools/build.ps1
```

本机功能测试（LCC64，可用 `-CompilerRoot` 指定安装目录）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/modbus/run.ps1
```

测试直接编译 RS485、ModBus、应用寄存器适配、采集和滤波的实际源码，
只替换 HAL 与 ADC 硬件接口。覆盖 CRC 标准向量、03/04、125 寄存器应答、
异常请求、广播、溢出、串口错误、收帧时序、中断竞争、DE 恢复、
正负 ADC 码和电压、持续采集、VOFA、去皮和数据过期状态。

这些验证不代替上板联调。上板需确认 DE、/RE 极性和接线、485 电气连接，
并用主站确认收到响应且数据随实际输入变化。

协议依据：[Modbus 串行规范 V1.02](https://www.modbus.org/file/secure/modbusoverserial.pdf)，
以及[Modbus 官方应用协议规范入口](https://www.modbus.org/modbus-specifications)。
